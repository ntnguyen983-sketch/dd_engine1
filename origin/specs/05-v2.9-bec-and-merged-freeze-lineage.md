# v2.9.x / BEC lineage — research and merged-freeze record

## v2.9 BEC runtime lineage

The v2.9 BEC material extended the runtime with a BEC observation layer and a stricter separation between Root/Core and observation/research. The UI guidance explicitly states that UI displays runtime results and must not introduce new computation rules.

The runtime prompt lineage retained the one-way pipeline and Core Lock: after initialization at t0, later layers cannot rewrite the root snapshot, moving lines or canonical identity.

## BEC architectural role

BEC is an observation/research layer over the computational result. It can inspect repetition, rhythm, density and related patterns, then describe how observed variables may correspond to state transition. It must not silently become a new Core formula.

## v2.9.2 merged-freeze lessons

The v2.9.2 merged-freeze material introduced a regression checklist covering:

- S00–S08 preservation;
- DWL and DPKE preservation;
- BEC density and BEC observation separation;
- no feedback loop from observation/warning/recommendation into Core;
- traceable risk/ROM evidence;
- recurrent/persistent calculations before interpretation;
- spacetime temporal/actor/topology/spatial contracts;
- evidence chains for warnings;
- forecast windows and uncertainty;
- deterministic canonical JSON/hash;
- dimension/version/constants/test-vector requirements for matrices.

It also explicitly marked unresolved matrix mappings, force-score/vector contracts, priority conflicts, F_norm and DPKE details for verification before freeze. This is important lineage evidence: unresolved formulas must remain unresolved rather than being silently completed by an implementation.

## BEC master audit

The BEC master restructuring retains canonical formulas where explicitly defined, but records missing numeric matrices/operators as registry/profile dependencies. The audit rule is explicit: the document must not fill gaps with new formulas merely to appear complete.

## Relation to v3.4

v3.4 keeps the architectural lesson and removes the temptation to make BEC labels into fixed ontology. BEC remains a possible dynamic/calibration observer. The permanent anchor is the architecture and expression discipline, not a claim that every historical BEC formula is eternal.
