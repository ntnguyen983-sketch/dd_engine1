# v2.8.6 — Frozen Core and deterministic pipeline

## Role in lineage

v2.8.6 is the major technical consolidation that became the Frozen Core for later 2.8.7 research/revision work.

## Input and pipeline

The lineage establishes a canonical input gate and a linear execution path:

`S00 Raw Input → S01 Normalize/SL-COL → S02 Structural Decode/PGL → S03 Topology/DPKE → S04 Rigid Checks → DWL → S05 Force Solver → S06 Field Solver → Firewall Gates → S07 Emergence → S08 Spacetime/Temporal Decision → Canonical JSON + SHA-256`

The exact implementation names varied between v2.8.6 variants, but the architectural separation is stable: raw data is normalized before computation, structural checks precede force calculation, firewalls stop invalid states, and the final record is canonicalized and hashable.

## Frozen Core principles

- deterministic forward-only execution;
- core identity and structural invariants are locked after canonical state creation;
- semantic interpretation cannot leak into pre-decoder computation;
- observations do not rewrite a previous snapshot;
- every important result must remain traceable to input and operators;
- extensions must not silently mutate the frozen core.

## Major computational families

- SL-COL / six-line structural operators;
- PGL/OCG/SIE graph representation;
- DWL dynamic weights combining base/context/interaction/time factors;
- DPKE phase velocity and delay;
- force and field calculations;
- five-dimensional field/Khí representation in the relevant v2.8.x lineage;
- rigid structure validation and execution firewall;

- canonical JSON and SHA-256 provenance.

## Boundary to later work

v2.8.6 is preserved as technical ancestry, not as a reason to freeze every historical variable forever. v2.8.7 introduced research/calibration layers precisely so uncertain hypotheses could be tested without silently mutating the core.
