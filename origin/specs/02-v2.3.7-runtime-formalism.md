# v2.3.7 — runtime formalism lineage

## Purpose

v2.3.7 expanded the v2.3.6 ontology into a full mathematical interaction/state pipeline. It is retained as a historical technical layer from which later runtime structures evolved.

## 7 layers

1. Universe — laws, philosophy and axioms.
2. Coordinate — reference frame.
3. Object — positioned object/actor.
4. Relation — interaction between positioned objects.
5. Dynamic Engine — computes dynamic change.
6. Evaluation — reports field/state objectively.
7. Interpretation — translates evaluated state into practical strategy.

## Dynamic chain

The runtime formalism expresses a sequence of the form:

`(M_i × M_j) --O_ij--> interaction I --R--> ΔS --Φ--> S(t+1) --decoder--> strategy`

The important architectural idea is the order of operations: calculate structure and dynamics first; decode meaning later. Semantic interpretation must not feed backward into the core calculation.

## Dynamic response

The historical v2.3.7 formalism includes a response function `R(S,O_ij)` that generates changes such as force, temporal delay and anchoring, followed by a trajectory integrator `S(t+1)=Φ(S(t),ΔS)`.

It also describes phase transitions from latent/compressed force to activation and propagation when force and interaction cross defined thresholds.

## Evaluation vs interpretation

Evaluation describes the physical/dynamic condition of the field without advice. Interpretation comes afterward and may construct actionable strategy from the evaluated trajectory.

## Lineage caution

Specific state labels, thresholds and decoder vocabulary are historical implementation details. They are preserved for traceability, but the current architectural anchor does not grant them immutable ontological status.
