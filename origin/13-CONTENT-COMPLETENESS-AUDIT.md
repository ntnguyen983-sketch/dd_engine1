## B. Explicitly unresolved / requires further source recovery

### B1. Earlier versions between v2.3 and v2.5

Search of the currently indexed Library/Conversation corpus did not surface authoritative standalone source documents for every remembered intermediate version (for example v2.4, v2.5.1 and v2.5.5). Do not invent their contents. Recover original artifacts if they exist.

### B2. v2.8.7_fixxx exact source pack

The general v2.8.7 BEC/fixxx lineage is represented, but the exact fixxx-BEC source set and every patch-level delta should be recovered and reconciled if source artifacts exist.

### B3. v3.0–v3.3 source lineage

The current anchor is represented, but the exact intermediate v3.0/v3.1/v3.2/v3.3 source artifacts and their distinct contributions should be recovered rather than inferred from the v3.4 summary.

### B4. Full implementation history

The archive has implementation-boundary documentation and a v2.9.2 reference implementation lineage. Exact repository code history, deployment experiments, UI test artifacts and production integration changes should be recovered if they contain materially different design decisions.

### B5. Canonical test vectors

Validation obligations are documented. A complete executable validation corpus with expected outputs for the active 3A anchor still needs to be built from source-approved formulas; it must not import superseded formulas by accident.

### B6. Raw source preservation

Where repository storage policy permits, original source artifacts should be preserved or their complete content should be represented in consolidated lineage documents. Summaries alone are insufficient if they lose a materially different rule or formula.

## Closure rule

Do not mark this audit CLOSED merely because every drawer has a README or because the number of documents looks large. Close only when the unresolved categories above have been checked against the available source corpus and either recovered, proven unavailable, or explicitly declared non-material.
