# Duyên Dịch — Foundational Lineage

## Purpose

This document consolidates the foundational conceptual lineage that must remain available to every later implementation. It is a historical/architectural source layer, not an executable rulebook by itself.

## Early invariant direction

Duyên Dịch began from the premise that observed things are not treated as fixed, isolated substances. A snapshot records a conditional configuration; the system studies the movement of the flow after that snapshot. The v2.3.6 kernel states that the hexagram is used to position a state, while the object of analysis is the Actor at the Thiên–Địa–Nhân intersection. fileciteturn54file14

The foundational philosophy is Đạo–Duyên–Dịch: interdependence / dependent arising and impermanence are treated as one operating principle; Duyên denotes an observed stable pattern of a condition network, while Dịch denotes its movement and transformation as conditions change. fileciteturn54file0

## Architectural discipline inherited from the early kernel

The early architecture established a freeze policy: constitutional principles, axioms, ontology, PGL/OCG, layered architecture, pipeline, firewall and traceability belong to the frozen architectural boundary; runtime engines, cost functions, adapters, plugins, APIs and SDKs remain extensible. fileciteturn54file0

The same lineage established semantic independence, primitive completeness, observer equivalence, information preservation, bidirectional traceability, fusion neutrality, decoder isolation and extensibility. fileciteturn54file3

## Impermanence / non-self constraint

The v2.8 lineage makes the constraint explicit: observed entities are snapshots within a flow, not fixed substances; conclusions are conditional and must change when the underlying condition set changes. The model therefore must not silently convert a temporary label into an intrinsic identity. fileciteturn54file4

Later v2.8.7 material reinforces semantic neutrality: kernel quantities describe geometric/dynamic state and must not directly inject subjective labels such as good/bad, auspicious/inauspicious, recommended or undesirable into the core. Unproven parameters remain hyperparameters rather than kernel laws. fileciteturn54file7

## Transition toward the current architectural anchor

The 2.8.7 Rev.B lineage separates Frozen Core, Research/BEC, Knowledge, Decoder/Inference and Evidence/Observer responsibilities. It requires one canonical core state, one initialization snapshot, deterministic computation, forward-only flow, core lock and continuous context. fileciteturn54file8

The current DD-3A architectural anchor consequently preserves the deeper invariant while allowing implementation terminology to evolve: identify what is being referenced, quantify observable relations in space/time, and describe qualities only as patterns grounded in quantities and evidence.

## Authority rule

This file preserves lineage. It does not erase earlier formulations merely because later language is cleaner. When a later anchor reconciles an earlier concept, the historical source remains evidence and the reconciled rule must be recorded separately.
