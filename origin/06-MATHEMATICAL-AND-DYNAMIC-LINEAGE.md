# DD ORIGIN — Mathematical & Dynamic Lineage

## Purpose

This document preserves the mathematical/runtime ideas that appeared before the current architectural anchor. It is historical source synthesis, not an instruction to import every historical formula into the current implementation.

## 1. Early computational direction

The v2.3 lineage introduced a layered computational model: Universe/axioms → Coordinate → Object → Relation → Dynamic Engine → Evaluation → Interpretation. The central rule was that a system must establish a reference frame and localization before relation, then dynamics, then evaluation, then interpretation. The v2.3.7 material explicitly separates these layers and defines state vectors, relation operators and runtime transitions.

## 2. State representation

Historical implementations used compact state vectors such as [H,L,K,T] and later [S,D,I,F,T]. They also used element matrices, Qi-state vectors, relation graphs, momentum/history and phase coordinates. These are preserved as lineage because they explain how the project moved from symbolic hexagram state toward a general dynamic representation.

## 3. Force and interaction

The lineage distinguishes structural relation from dynamic force. Historical operators included Sinh/Khắc matrices and interaction operators such as Xung/Hợp. These must be treated as versioned model components, not universal facts. Their exact constants belong to the source version in which they were defined.

## 4. v2.5 research branch

v2.5.3 introduced a more abstract mathematical layer with a primitive configuration potential Psi and derived quantities such as energy density, force and potential surface. The source itself states that these are modeling axioms, not experimentally verified natural laws. Therefore this material belongs in Research/History unless a later canonical contract explicitly adopts it.

## 5. v2.8.x computational foundation

v2.8.x consolidated S00–S08, deterministic forward-only execution, DWL, L2-RGS, DPKE, Spacetime, BEC, warning/forecast/recommendation and canonical JSON/hash contracts. Later merged documents emphasize that BEC/Research and knowledge layers must not silently mutate frozen core state.

## 6. v2.9.2 merged implementation lineage

The v2.9.2 merged reference implementation combined deterministic matrix core, DWL, DPKE, BEC observation, emergence, spacetime, ROM, warning, implication, forecast, recommendation and canonical JSON. Its regression checklist requires deterministic hashing, dimensions/version/constants/test vectors, evidence chains and no observation-to-core feedback.

## 7. Current architectural interpretation

The current DD-3A anchor does not require historical equations to remain canonical. It preserves the architecture of observation → interaction → dynamics/rhythm → transition → ground truth/calibration, while reducing the final representational vocabulary to **Định danh | Định lượng | Định tính**.

## Boundary rule

Historical equations are evidence of lineage. They become executable authority only when explicitly included in the current Canonical Contract or an implementation profile.
