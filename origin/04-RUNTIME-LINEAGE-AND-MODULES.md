## 3A dynamic execution layer

The 3A lineage generalizes the runtime world beyond a particular object type. Its basic computational objects are:

- entity/reference stream;
- observation;
- interaction event;
- spatial node;
- temporal sequence;
- measured flow/force;
- state transition;
- evidence/ground truth.

The crucial architectural distinction is that `B(V_k)` belongs to the spatial node `V_k`, while `N_i` is a referenced participant/observation stream. Occupying a bottleneck does not make the entity itself the bottleneck.

`event_count`, `cycle_count` and `K_rep` are separate measurements: event incidence, graph topology and temporal motif repetition respectively.

`σ_rhythm` is computed from ordered timestamps of the same relation/motif. It is not a flat timestamp count.

## Current calibration rule

A reference implementation must never manufacture `f_BEC`, `f_net_out`, `R(t)`, `S07` or any other dynamic/calibration quantity when the canonical source does not define the required input/formula. The value must remain unavailable/`None` or explicitly require L4/ground truth.

## Implementation derivation rule

The Origin is not required to contain one giant executable. Instead it must provide enough source-backed contracts for implementation branches to be derived independently:

`origin → canonical contract → adapter → implementation → validation suite → production runtime`.

Every implementation branch must declare the Origin sections it implements and must not silently promote historical research formulas to canonical laws.
